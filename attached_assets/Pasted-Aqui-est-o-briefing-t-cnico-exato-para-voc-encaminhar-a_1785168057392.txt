Aqui está o briefing técnico exato para você encaminhar ao Dr. Replit. Quanto mais preciso for o contrato, mais rápida e segura fica a integração.

---

1. Endereço público do endpoint

Preciso da URL completa, acessível da internet, sem autenticação prévia. Exemplo:

```
POST https://api.padaxor.com.br/api/vitrine-leads
```

Se houver ambiente de homologação/testes, me envie também:

```
POST https://api-homolog.padaxor.com.br/api/vitrine-leads
```

---

2. Campos do corpo da requisição (JSON)

O formulário da vitrine pública vai capturar apenas:

| Campo | Tipo | Obrigatório | Regras |
|-------|------|-------------|--------|
| `name` | string | sim | nome completo; mínimo 3 caracteres; máximo 100 |
| `phone` | string | sim | telefone com DDD; aceitar apenas dígitos, hífen, espaço e parênteses; mínimo 10 dígitos, máximo 15 |
| `cnpj` | string | não | apenas se o interessado marcar “sou clínica”; 14 dígitos ou formato `XX.XXX.XXX/XXXX-XX` |
| `source` | string | não | identificador da campanha/página; sugerir fixo `"padaxor-vitrine"` |
| `utm` | objeto | não | campos opcionais `utm_source`, `utm_medium`, `utm_campaign`, `utm_content`, `utm_term` |

Exemplo mínimo:

```json
{
  "name": "Dra. Fernanda Lima",
  "phone": "(11) 99999-8888",
  "source": "padaxor-vitrine"
}
```

Exemplo com clínica:

```json
{
  "name": "Clínica Vitale",
  "phone": "(11) 99999-8888",
  "cnpj": "12.345.678/0001-90",
  "source": "padaxor-vitrine"
}
```

---

3. Resposta esperada da API

Sucesso — lead registrado e acesso liberado

```json
{
  "success": true,
  "access_token": "vit_abc123...",
  "expires_at": "2026-07-28T14:38:00Z",
  "lead_id": "uuid-ou-codigo-interno"
}
```

- `access_token` será guardado no `localStorage` do navegador para liberar a vitrine.
- `expires_at` ajuda a re-exibir o portão quando o acesso expirar.

Erro de validação (400)

```json
{
  "success": false,
  "error": "INVALID_PHONE",
  "message": "Telefone inválido. Verifique o DDD."
}
```

Erro de duplicidade (409)

```json
{
  "success": false,
  "error": "LEAD_EXISTS",
  "message": "Este telefone já está registrado. Aguarde nosso contato."
}
```

Erro de rate limit (429)

```json
{
  "success": false,
  "error": "RATE_LIMIT",
  "retry_after": 60
}
```

---

4. Segurança mínima necessária

Peça ao Dr. Replit para garantir:

- Rate limiting por IP: no máximo 3 tentativas por minuto e 10 por hora.
- Lista de bloqueio (blocklist): rejeitar domínios/telefones de teste descartáveis.
- Sanitização: a API deve limpar e normalizar `phone` e `cnpj` antes de salvar.
- CORS: liberar o domínio do site institucional (`https://padaxor.lovable.app` e o domínio próprio futuro, se houver).
- HTTPS obrigatório: nunca aceitar HTTP.
- Não exigir autenticação: este endpoint é público, pois é justamente o portão de entrada.

---

5. Onde o lead deve ser salvo

A API pode salvar onde for mais conveniente para o sistema de vocês (banco do `api-server`, planilha, CRM, etc). O importante é que o frontend só precise do endpoint acima.

Se for possível, peça para que o lead também seja sincronizado para a tabela `leads` do Supabase (a que já existe no projeto), mas isso é opcional — o frontend não depende disso.

---

6. Duração do acesso liberado

Sugiro que o `access_token` da vitrine dure 24 horas (ou 12 horas, se preferir manter o mesmo padrão do login de colaboradores). Assim o portão não fica incomodando o usuário a cada clique.

Quando expirar, o site exibe o portão novamente.

---

7. Formato ideal de entrega

O ideal é o Dr. Replit te responder com:

1. URL do endpoint (produção e homologação).
2. Um exemplo de `curl` funcionando.
3. Uma tabela ou JSON com todos os códigos de erro possíveis.
4. Confirmação de que CORS está liberado para o domínio do site.
