A.1 — POR QUE NÃO PELO MCP

A ponte MCP não executa SQL. Ela opera a plataforma: serviços, variáveis,
domínios, logs, deploys. Não há ferramenta de banco. E o seu dump precisa
do cliente psql de verdade — tem 155 blocos `COPY ... FROM stdin` e usa
`\restrict`, que são comandos do psql, não SQL comum.

Nenhum de nós dois sobe isso por MCP. É CLI.

A.3 — O CAMINHO CORRETO: TÚNEL SSH, SEM EXPOR O BANCO

O Postgres do Railway não tem proxy TCP público, e não vamos criar um —
seriam 3.683 fichas de cliente acessíveis pela internet. A CLI resolve
isso com um túnel SSH temporário.

  TERMINAL 1 — abre o túnel e deixa aberto:

    railway login
    railway link
    railway connect Postgres --tunnel-only

  Ele imprime host, porta, usuário, senha e a URL completa de conexão, e
  segura o túnel até você dar Ctrl+C. Copie a URL.


A.4 — A CARGA, EM UMA TRANSAÇÃO SÓ

  TERMINAL 2 — com o túnel aberto:

    # 1. Estrutura das tabelas fora do schema Drizzle.
    #    Rode ANTES e sozinho: são CREATE TABLE idempotentes.
    psql "<URL_DO_TUNEL>" -v ON_ERROR_STOP=1 \
      -f exports/railway/00-extras-estrutura.sql

    # 2. Limpeza + dados NA MESMA TRANSAÇÃO.
    psql "<URL_DO_TUNEL>" -v ON_ERROR_STOP=1 --single-transaction \
      -f exports/railway/01-truncate.sql \
      -f exports/railway/02-dados.sql

  ESTA É A PARTE MAIS IMPORTANTE DA CARTA.

  Os dois `-f` na mesma chamada, com `--single-transaction`, fazem o
  TRUNCATE e a carga rodarem numa transação única. Se a carga falhar no
  bloco 90 de 155, o TRUNCATE é desfeito junto e o banco volta exatamente
  ao estado anterior.

  Se você rodar os dois arquivos em chamadas separadas — que é como o seu
  LEIA-ME descreve — uma falha no meio deixa o banco VAZIO, com o truncate
  já efetivado e os dados pela metade. Esse é o cenário que precisamos
  impedir.

  `ON_ERROR_STOP=1` faz o psql parar no primeiro erro em vez de seguir
  engolindo falhas. Sem ele, o psql continua e você recebe um "terminou"
  enganoso.


A.5 — SE FALHAR

Não tente remendar. Leia o erro, corrija o dump, e rode de novo do zero.
A transação garante que o estado anterior está intacto. Repetir é barato;
consertar meio banco não é.
