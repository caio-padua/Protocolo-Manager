Assunto: Ferramentas e arquitetura usadas para construir o site institucional PADCON Platform®

Dr. Replit Manager,

Esta carta explica, do ponto de vista técnico, como foi construído o site institucional do PADCON Platform®, para que você possa entender o padrão adotado, reutilizar componentes se necessário, e manter consistência visual com o ecossistema PADCOM.

1. ESTRUTURA GERAL DO REPOSITÓRIO

1.1. O projeto vive num monorepo gerenciado pelo pnpm workspaces — uma forma de organizar vários produtos no mesmo repositório, cada um com suas próprias dependências.
1.2. O gerenciador de pacotes é o pnpm (versão dez) — mais rápido e econômico em disco que o npm convencional.
1.3. A linguagem base é TypeScript 5.9 — JavaScript com verificação estática de tipos, que evita erros silenciosos no código.

2. FERRAMENTAS DO SITE PADCON PLATFORM®
Ferramenta	O que é	Para que foi usada
React 18	Biblioteca de interface criada pelo Facebook	Montar cada seção da página como componente independente
Vite	Servidor de desenvolvimento e empacotador moderno	Compilar e servir o site em alta velocidade
Tailwind CSS	Framework de estilos baseado em classes	Estilizar cada elemento diretamente no HTML, sem escrever CSS separado
TypeScript	Versão tipada do JavaScript	Garantir que nenhum componente receba dados errados
pnpm	Gerenciador de pacotes	Instalar e organizar todas as dependências

3. ARQUITETURA DO SITE

3.1. O site tem uma única variante ativa chamada Haute Horlogerie — um conceito visual que remete à relojoaria suíça de alta precisão, escolhido pelo Dr. Caio como identidade permanente do PADCON Platform®.
3.2. Toda a estrutura de seções vive em artifacts/padcon-platform/src/variants/haute/ — cada seção é um arquivo separado (Hero, Founder, CaseStudy, Ecosystem, Architecture, Testimonials, Practice, Journey, FinalCta).
3.3. Todo o texto do site — em português e em inglês — vive num único arquivo central: src/content/haute.ts. Nenhum texto está "embutido" dentro dos componentes.

4. SISTEMA BILÍNGUE

4.1. O site alterna entre português (Brasil) e inglês com um único hook (gancho de código) chamado useLang().
4.2. O padrão de uso é: copy[lang] — onde lang vale "pt" ou "en" dependendo do idioma ativo.
4.3. Essa lógica vive em src/i18n/LanguageContext.tsx.

5. SITE DA PARXIS

5.1. O segundo produto — PARXIS, site comercial da PAWARDS para clínicas de medicina integrativa — também vive no mesmo monorepo, no artefato artifacts/parxis/.
5.2. Ele usa o mesmo stack: React + Vite + Tailwind + TypeScript.
5.3. O logo da PARXIS foi processado com ImageMagick — uma ferramenta de linha de comando para manipulação de imagens — para extrair o símbolo e o wordmark (texto do logotipo) com canal alfa (fundo transparente) a partir do arquivo original.
5.4. O site da PARXIS é servido no caminho /parxis/ dentro do mesmo proxy reverso que serve o PADCON Platform® em /.

6. PROXY REVERSO E ROTEAMENTO

6.1. Um proxy reverso é um servidor intermediário que recebe todas as requisições e as encaminha para o serviço correto baseado no caminho da URL.
6.2. No Replit, esse roteamento é configurado pelo arquivo artifact.toml dentro de cada artefato — ele declara a porta local e o caminho público.
6.3. O PADCON Platform® responde em / e o PARXIS responde em /parxis/.

7. VERIFICAÇÃO DE QUALIDADE

7.1. O comando de verificação preferido é pnpm --filter @workspace/padcon-platform run typecheck — ele verifica erros de tipo sem precisar compilar o projeto inteiro.
7.2. O comando build não é usado para verificar, pois ele exige variáveis de ambiente (PORT e BASE_PATH) que só existem durante o workflow em execução.
