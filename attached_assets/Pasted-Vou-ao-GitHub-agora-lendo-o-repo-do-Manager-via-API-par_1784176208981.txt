🚨 FALHAS CRÍTICAS (em ordem de severidade)

FALHA 1 — SEGURANÇA: API expõe tokens de terceiros sem autenticação

O GET /api/empresas retorna a row COMPLETA da tabela, que inclui:
Campo exposto	O que vaza
twilioAccountSid + twilioAuthToken	Credenciais Twilio da clínica — quem pegar envia WhatsApp
zapsignToken	Token API do ZapSign — quem pegar assina documentos
waToken	Token WhatsApp Business
telegramBotToken	Token do bot Telegram
certFileId + certStatus	Localização do certificado digital ICP-Brasil

O collaboratorGuard (no index.ts) protege só escritas das rotas site-content e cadastros. As rotas de empresas ficam FORA. Qualquer usuário autenticado — e dependendo do guard, qualquer um — lê esses campos.

Fix obrigatório: GET /api/empresas deve omitir todos os campos de credencial; criar sub-rota GET /api/empresas/:id/integracoes protegida por perfil owner/admin.

FALHA 2 — ARQUITETURA: clients, professionals, sessions não têm empresa_id

O fluxo que o Manager quer construir é:

PAXTER licencia empresa X → empresa X tem clientes → clientes fazem consultas → geram RAS

Mas o banco atual:
Tabela	Tem empresa_id?	Consequência
empresas	É a própria âncora	—
cargos	Sim (empresa_id FK)	OK
colaboradores	Sim (empresa_id FK)	OK
clients	NÃO (tem só locationId)	Clientes são globais — impossível isolamento
locations	NÃO tem FK para empresas	Clínica física não sabe a qual empresa pertence
sessions	NÃO	Consultas são globais
prescriptions	NÃO	Receitas são globais
ras	NÃO	Registros são globais

Sem isso: empresa_id existe na tela, mas NÃO filtra nada no banco. É o Context Switcher sem a chave real.
