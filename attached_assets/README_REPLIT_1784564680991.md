# PARXIS — Motor de arabescos com duas estratégias

## Diagnóstico do erro atual

O layout anterior não falha por falta de beleza; falha por arquitetura:

1. O ornamento está sendo tratado como um desenho que a LLM deve recriar.
2. O SVG é usado como `background-image` externo; alguns geradores de PDF não carregam corretamente fundos externos.
3. O tile pode ter área transparente nas extremidades, causando emendas.
4. Os cartões escondem quase toda a faixa porque não há relação fixa entre:
   - altura da faixa;
   - altura dos cartões;
   - centro vertical.
5. As variantes estão codificadas diretamente na tela, e não registradas como modelos.
6. Alterar `background-size` muda o desenho de modo imprevisível.

## Estratégia A — SVG inline

Use `renderMode: "inline-svg"`.

Vantagens:
- vetor real;
- nitidez ilimitada;
- menor arquivo;
- melhor PDF;
- cores e densidade configuráveis;
- não depende de carregar imagem de fundo externa.

A faixa é um `<svg>` real no DOM, com `<pattern>`, atrás dos cartões.

## Estratégia B — faixa pronta em PNG/WebP

Use `renderMode: "raster-strip"`.

Vantagens:
- o Replit não redesenha nada;
- aparência exatamente igual à imagem aprovada;
- implementação simples;
- excelente como fallback.

Limitações:
- não é editável como vetor;
- precisa de imagem em 300 dpi;
- cada desenho novo exige novo arquivo.

Os PNGs fornecidos têm proporção 186 mm × 24 mm e resolução 2325 × 300 px.

## Recomendação

- Produção/PDF: SVG inline.
- Fallback ou modelo visual fechado: PNG pronto.
- O seletor usa o mesmo `modelId` nas faixas superior e inferior.
- Salvar `modelId` no cadastro do template ou da clínica.

Exemplo de banco:

```ts
interface PrescriptionTemplateRecord {
  id: string;
  name: string;
  arabesqueModelId: ArabesqueModelId;
  isDefault: boolean;
}
```

## Regra de camadas

- z-index 0: faixa completa de ponta a ponta.
- z-index 2: cartões brancos.
- z-index 3: textos.

A faixa nunca deve ser criada como dois pedaços laterais.
